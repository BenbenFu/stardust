## 后续如需重新子集化
`subset_user_ttf.py`（在构建环境 / 任意装了 fonttools 的机器运行）：
```bash
# 把 TTF 放 web/font/ 顶层，然后：
python subset_user_ttf.py
```
脚本会按文件名映射（站酷快乐体→圆体 / LXGWWenKai→楷体 / SarasaGothicSC→等宽），
子集化到 GB2312 woff2 并覆盖 `regular.woff2`。覆盖后请自增 `fonts.css` 的 `?v=` 版本号
（或硬刷新）以避免浏览器缓存旧字体。

## 格式要求
- 交付用 **woff2**（浏览器全支持、体积最小）。不要直接放 TTF/OTF（太大）。
- **CJK 必须子集化**：完整中文 5–30MB，裁到 GB2312（约 6763 常用字）后每个 1–3MB。

## 子集化要点（GB2312 不是单个 Unicode 区间）
GB2312 不能简单用 `--unicodes=U+xxxx-U+xxxx` 表达，需用「字符清单」驱动。
本项目用 Python 生成 GB2312 全字符再喂给 fonttools（见 `fetch_ideal_fonts.py` 内的
`gb2312_text()`）。等价命令行做法：
```bash
# 1) 生成 GB2312 字符清单
python -c "import sys; sys.stdout.write(''.join(bytes([0xA0+q,0xA0+w]).decode('gb2312') for q in range(1,95) for w in range(1,95)))" > gb2312.txt
# 2) 子集化
pyftsubset 源.ttf --output-file=web/font/黑体/regular.woff2 --flavor=woff2 \
  --text-file=gb2312.txt --no-hinting --desubroutinize
```
- 想更小：把清单换成常用 3500 字，体积可压到几百 KB。

## 启用步骤（整体）
1. Supabase 执行 `web/style_font_localize_20260720.sql`（把 DB 九选项显示名改为中文分类，
   并指向本文件声明的 `FontX` 字体族）。
2. 硬刷新预览页 / 画廊页（Ctrl+Shift+R）重拉模板与字体。
3. 圆体/楷体/等宽 现已是理想字体，无需再跑 `fetch_ideal_fonts.py`。

## 注意
- 文件夹用中文名在本地/GitHub Pages 均正常；若部署出现编码问题，改名成拼音
  （hei/song/...）并同步改 `fonts.css` 路径即可。
- 替换字体文件后若浏览器不刷新：自增 `fonts.css` 里对应 `?v=`（或硬刷新）。
- 引擎 `style-engine.js` 不用动，它只发射 `data-style-typo-font-family-*` 属性，
  真正字体名在 DB 模板与本 `fonts.css` 里。
