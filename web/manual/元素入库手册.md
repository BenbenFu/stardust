# 卡片元素入库手册（Agent 专用 · 写 CSS / 写 SQL / 入库）

> **读者**：要**设计新元素**（bg_pattern / corner_badge / floating_deco / edge_deco / header_deco / side_accent / divider 任一子维度）或**改现有组件 CSS** 的 agent。
> **前提**：你已会拼 `style_json`（不会先读同目录《拼装手册.md》）。本手册只讲「怎么把一个新的视觉效果写进数据库、且不与其它装饰打架」。
> **你无数据库写权限**：本手册所有改动都产出 SQL，交用户审核执行。
> **手册时效性（2026-07-26 校正）**：2026-07-25 曾有一轮「主合成收归引擎 BASE_CSS」（`element_strip_composite_20260725.sql` + reorder 轮），**已因实测"验证页几乎不显示"整体作废**，引擎回退 `20260724a`、DB 已回退到 reorder 前。本手册以**当前真实架构**为准（每个背景类模板自带逐字一致 14 槽主合成块 + `floating_circle` 隔离到专属层），与 `style-engine.js?=20260724a` 及线上 DB 现状一致。

---

## 1. 何时需要入库

- 主题需要一种现有 `value` 里没有的视觉（全新渐变 / 新气泡形状 / 新角标 / 新背景纹理…）。
- 需要新「容器组」结构（带特定 `field_slot_map`/`extra_css`）。
- 发现某现有组件的 `css_template` 有明显缺陷（提 fix SQL）。

> **不要自己写 CSS 塞进 `style_json`**。任何新视觉效果都必须作为数据库维度表的一条 `css_template` 存在，否则引擎不认。

## 2. 渲染机制总览（写对 CSS 的前提）

### 2.1 四个装饰子维度各发射一个独立属性
`.gallery-card[data-style-element-corner=...]` / `[data-style-element-bg=...]` / `[data-style-element-edge=...]` / `[data-style-element-float=...]`。四者互不互斥，**可同时开启**。

### 2.2 三类实现方式（设计前先定类）

| 类 | 占用 | 适用 | 例子 |
|---|---|---|---|
| **背景类 css_background** | 14 槽画布 | 角标/背景纹/边缘/浮动 中"画图"的 | dot_grid、circle_stamp、bracket_frame、scatter_dots（**floating_circle 已隔离到专属层，见 §2.4 / §8 案例 7，不再占画布 float 槽**） |
| **伪元素类 pseudo_before/after/both** | 卡片伪元素（文字） | 角标丝带、标签、菱形 | corner_ribbon(::after)、tamagotchi_label(::before)、art_deco_diamond(.card-deco-layer) |
| **正交类 css_mask / css_clip** | 遮罩/裁切 | 齿孔、切角 | stamp_perforation(mask)、notched_corner(clip) |

### 2.3 共享 14 槽背景画布（背景类装饰能叠加的根本）

卡片根固定一块 14 槽背景画布，**槽位顺序不可改**：
```
角标 corner-1,2 | 边缘 edge-1,2,3,4 | 背景纹 bg-1,2,3,4 | 浮动 float-1,2,3,4
```

**当前真实架构（2026-07-26 校正）**：引擎 `BASE_CSS`（`style-engine.js?=20260724a`）**不含** 14 槽主合成，只有 `.gallery-card{ background: var(--card-bg) }`。让画布工作的，是**每个背景类 element 模板各自带一份逐字一致的 14 槽主合成块**（见 §4.1）。这是 2026-07-23 定稿、并在 2026-07-25「主合成收归引擎」那一轮被作废回退之后的最终状态。

**14 槽主合成的「所有权」契约（关键，直接回应"多组件打架"）**：

主合成块是一份**全项目共享、逐字一致**的契约，不是某个组件私有：
1. **契约内容固定**：`background-image/-size/-position/-repeat` 四个属性，各 14 个 `var()` 引用，顺序严格 `corner,edge,bg,float`，全部带兜底（`none` / `auto` / `no-repeat`）。任何背景类模板的主合成块必须与此契约**逐字相同**，不得增删、不得改顺序、不得在 `var()` 外夹裸关键字（见 §8 案例 6）。
2. **槽位变量归各组私有**：bg 装饰只 `SET` 自己的 `--el-bg-*`，corner 装饰只 `SET` `--el-corner-*`，依此类推。**绝不许跨组写槽**（bg 装饰写 `--el-float-*` 会污染浮动槽，见 §8 案例 2）。
3. **为什么这样就不打架（层叠争用的真实机制）**：当两个背景模板（如 starfield 的 bg + scatter_dots 的 float）同卡，二者对 `background-image` **同特异性、源码顺序后者胜属性**。但二者主合成块**逐字一致** → 胜出那条引用的仍是**全部 14 槽变量**，而每条模板只负责自己那组的变量、且都已设到同一元素上 → 所有图层都正常解析。**层叠只决定"哪条规则的值生效"，而值本身引用了所有变量，所以结果正确。** 一旦某模板偏离契约（缺主合成 / 主合成不一样 / 夹裸关键字），层叠就会把别的组的图层整组抹掉或平铺——这正是 §8 案例 0 的根因。
4. **独占范围（每子维度占哪些槽）**：`corner_badge`→corner-1,2；`edge_deco`→edge-1..4；`bg_pattern`→bg-1..4；`floating_deco` 中走画布的 `scatter_dots`→float-1,2。`floating_circle` **例外**：已脱离画布，见 §2.4 / §8 案例 7。

> ⚠️ **关于"方案 A/B/C"（星空纹理作者曾提议）**：曾考虑 ① 仅布局组件输出主合成、装饰只写变量（方案 A）；② 定义槽位独占优先级、交叉写入报错（方案 B）；③ 引擎做变量级合并（方案 C）。**当前部署采用"逐字一致契约"式**——效果等价于方案 A 的意图（保证"主合成唯一来源且逐字一致"这一不变量），但由每个模板重复同一份契约实现，而非引擎集中。任何改法都必须守住"主合成只此一份且逐字一致"的不变量，否则层叠争用复发。

> ⚠️ **背景类铁律（最高优先级）**：
> 1. **每个背景类模板都必须输出完整且逐字一致的 14 槽主合成块**（机械复制 §4.1 的"契约块"，不要手改）。缺失或改动的模板会重新引入层叠争用（见 §8 案例 0）。
> 2. **只 `SET` 自己组的槽位变量**，绝不写别的组的 `--el-*`（如 bg 装饰禁止写 `--el-float-*`）。
> 3. 颜色只引用 `--card-bg/-text/-accent/-muted`（及 `-rgb`），禁止硬编码 hex。
> 4. 主合成块里**禁止在 `var()` 之外出现任何裸 CSS 关键字**（如多拼一个 `repeat`）——见 §8 案例 6。

### 2.4 伪元素分配表 + 兼容性矩阵

| 伪元素 | 授权给 | 用途 |
|---|---|---|
| `.gallery-card::before` | tamagotchi_label | 顶部字样 |
| `.gallery-card::after` | corner_ribbon | 角标丝带 |
| `.card-deco-layer::before` / `::after` | art_deco_diamond | Art Deco 菱形带（双伪元素独占） |
| `.card-deco-layer::before` | floating_circle（隔离层） | 浮动圆。**与 diamond 单选互斥**（同属 `floating_deco` 单选维度），该伪元素对 floating_circle 永远空闲，故可安全复用 |

文本类三者互不争用（菱形挂在引擎注入的专属层 `.card-deco-layer`，与卡片根伪元素解耦），可同时开 3 个。背景类与文本类天然正交，永远 ✅。

> **floating_circle 现在还"容易坏"吗？** 不容易了。历史上它脆弱，是因为它和 bg_pattern **共用同一块 14 槽画布**、写 `--el-float-1` 占 float 槽，组合时被层叠连坐（见 §8 案例 0 / 时间线）。**2026-07-25 修复（现行）**：floating_circle 已**脱离画布、隔离到 `.card-deco-layer::before`**，读引擎发射的 `--el-float-pos-*` 锚点变量，与 bg 画布正交 → 永不再争抢（见 §8 案例 7）。注意：这不是"主合成收归引擎"（那一轮已作废），而是"被连坐元素搬到独占层"的外科手术式修复。文本类装饰（丝带/标签/菱形）本就走伪元素独立通道，与画布正交，不受影响。

## 3. 配色槽位映射透明化（禁止硬编码颜色）

`style_palette_options` 每条记录的四个颜色列存的是「harmony 种子色生成的 10 阶色阶**索引号**」（字符串如 `"3"`），**不是 hex**。引擎按 `tone`/`slot` 解析后注入卡片根 CSS 变量；你**只引用这四色，禁止写死 hex**。

| 数据库列 | 语义 | 注入变量 | 用途 |
|---|---|---|---|
| `bg` | 背景色阶索引 | `--card-bg` | 卡片底 / 浮层底 |
| `text_color` | 文字色阶索引 | `--card-text` | 主文字 |
| `accent` | 强调色阶索引 | `--card-accent` | 色条/边框/强调 |
| `muted` | 次要色阶索引 | `--card-muted` | 次要文字/描边 |

另有 `--card-accent-rgb` / `--card-bg-rgb`（如 `224,86,63`）供 `color-mix(in srgb, var(--card-accent) 60%, transparent)` 做透明混色。换 palette 整卡配色应自动联动——需要额外强调色优先靠 `slot` 的 `shift_*` 派生。

## 4. 标准入库写法（CSS 规范）

可调色槽：`--card-bg` / `--card-text` / `--card-accent` / `--card-muted`（及 `-rgb`）。

### 4.0 变量命名规范（最高优先级 · 全项目唯一标准）

手册历史上多次因"同一槽位被不同组件用不同变量名"而打架（星空作者曾用 `--el-float-pos-1`、floating_circle 旧形态用 `--el-float-anchor-pos`，两者名不对版、永远串不起来）。**所有组件必须严格遵守下表，禁止自行发明变量名。** 存在**两套独立机制**，切勿混淆：

**机制 A — 14 槽共享画布变量（背景类装饰写、引擎主合成读）**
槽位顺序固定：`corner-1,2 | edge-1,2,3,4 | bg-1,2,3,4 | float-1,2,3,4`。每个槽位四件套：

| 槽位 | 图像 | 尺寸 | 位置 | 重复 |
|---|---|---|---|---|
| `corner-{1..2}` | `--el-corner-{n}` | `--el-corner-size-{n}` | `--el-corner-pos-{n}` | `--el-corner-rep-{n}` |
| `edge-{1..4}` | `--el-edge-{n}` | `--el-edge-size-{n}` | `--el-edge-pos-{n}` | `--el-edge-rep-{n}` |
| `bg-{1..4}` | `--el-bg-{n}` | `--el-bg-size-{n}` | `--el-bg-pos-{n}` | `--el-bg-rep-{n}` |
| `float-{1..4}` | `--el-float-{n}` | `--el-float-size-{n}` | `--el-float-pos-{n}` | `--el-float-rep-{n}` |

> 注意：`--el-float-{n}` / `--el-float-size-{n}` / `--el-float-pos-{n}` / `--el-float-rep-{n}` 是**画布上的 float 槽位**（被 scatter_dots 等背景类浮动装饰使用），与下方机制 B 的锚点变量**完全不同**。

**机制 B — 锚点定位变量（引擎发射、装饰消费，用于 8 锚点贴角/贴边）**
仅 `corner` 与 `float` 两类支持位置锚点，引擎在卡片根注入（见 `style-engine.js` `emitAnchorVars`）：

| 变量 | 含义 | 由谁设 | 由谁用 |
|---|---|---|---|
| `--el-{corner\|float}-anchor-pos` | 背景型装饰的 `background-position` 兜底串 | 引擎 | 背景型（circle_stamp / dot_status / scatter_dots 的槽位定位） |
| `--el-{corner\|float}-pos-top/right/bottom/left` | 伪元素/隔离层四边定位 | 引擎 | 伪元素型（丝带/标签）与隔离层（floating_circle 现形态） |
| `--el-{corner\|float}-pos-tf` | 居中补偿 transform | 引擎 | 伪元素型 / 隔离层 |

> 注意：机制 B 的 `--el-float-pos-top/right/bottom/left/tf` 是 **floating_circle 隔离层（`.card-deco-layer::before`）的定位变量**，与机制 A 的 `--el-float-{n}` 画布槽**互不干扰**。模板只 `var(--el-xxx, 原生兜底)` 消费，**不得自己发明** `--el-float-pos-1` 之类名字。

**铁律**：
1. 背景类装饰只写**本组**的机制 A 槽位变量（如 bg 装饰只写 `--el-bg-*`），通过 §4.1 的逐字一致主合成块被引擎读取。
2. 锚点定位一律走机制 B 的引擎变量，模板只消费，**不得自行发明变量名**。
3. 颜色只引用 `--card-bg/-text/-accent/-muted`（及 `-rgb`），禁止硬编码 hex。

### 4.1 背景类模板（必带逐字一致主合成 + 只 SET 本组变量）

> **最小可用模板**（bg_pattern 为例）。`【契约块】` 是机械复制、逐字一致的 14 槽主合成，**所有背景类模板共用同一份，禁止手改**；`【本组变量】` 才是你每次要填的部分。

```css
.gallery-card[data-style-element-bg="your_value"] {
  /* ===== 【本组变量】人工填写：只写自己组的 --el-bg-* ===== */
  --el-bg-1: radial-gradient(circle, var(--card-muted,#ccc) var(--el-geo-thick, 1px), transparent calc(var(--el-geo-thick, 1px) + 0.6px));
  --el-bg-size-1: var(--el-geo-gap, 16px) var(--el-geo-gap, 16px);
  --el-bg-pos-1: 0 0;
  --el-bg-rep-1: repeat;
  /* （bg-2..4 同理，不用则留空，主合成兜底 none 自动隐藏） */

  /* ===== 【契约块】机械复制，逐字一致，禁止改动/缺失 ===== */
  background-image:
    var(--el-corner-1, none), var(--el-corner-2, none),
    var(--el-edge-1, none), var(--el-edge-2, none), var(--el-edge-3, none), var(--el-edge-4, none),
    var(--el-bg-1, none), var(--el-bg-2, none), var(--el-bg-3, none), var(--el-bg-4, none),
    var(--el-float-1, none), var(--el-float-2, none), var(--el-float-3, none), var(--el-float-4, none);
  background-size:
    var(--el-corner-size-1, auto), var(--el-corner-size-2, auto),
    var(--el-edge-size-1, auto), var(--el-edge-size-2, auto), var(--el-edge-size-3, auto), var(--el-edge-size-4, auto),
    var(--el-bg-size-1, auto), var(--el-bg-size-2, auto), var(--el-bg-size-3, auto), var(--el-bg-size-4, auto),
    var(--el-float-size-1, auto), var(--el-float-size-2, auto), var(--el-float-size-3, auto), var(--el-float-size-4, auto);
  background-position:
    var(--el-corner-pos-1, 0 0), var(--el-corner-pos-2, 0 0),
    var(--el-edge-pos-1, 0 0), var(--el-edge-pos-2, 0 0), var(--el-edge-pos-3, 0 0), var(--el-edge-pos-4, 0 0),
    var(--el-bg-pos-1, 0 0), var(--el-bg-pos-2, 0 0), var(--el-bg-pos-3, 0 0), var(--el-bg-pos-4, 0 0),
    var(--el-float-pos-1, 0 0), var(--el-float-pos-2, 0 0), var(--el-float-pos-3, 0 0), var(--el-float-pos-4, 0 0);
  background-repeat:
    var(--el-corner-rep-1, no-repeat), var(--el-corner-rep-2, no-repeat),
    var(--el-edge-rep-1, no-repeat), var(--el-edge-rep-2, no-repeat), var(--el-edge-rep-3, no-repeat), var(--el-edge-rep-4, no-repeat),
    var(--el-bg-rep-1, no-repeat), var(--el-bg-rep-2, no-repeat), var(--el-bg-rep-3, no-repeat), var(--el-bg-rep-4, no-repeat),
    var(--el-float-rep-1, no-repeat), var(--el-float-rep-2, no-repeat), var(--el-float-rep-3, no-repeat), var(--el-float-rep-4, no-repeat);
}
```

> 📐 **几何纹理尺寸/间距统一控制（2026-08-05）**：背景平铺类纹理（dot_grid / fine_grid / horizontal_lines / terminal_scanlines / grain_noise）与浮动散点（scatter_dots）的尺寸与间距**不再硬编码**，改引用引擎按需发射的 `--el-geo-gap`（间距/步长）与 `--el-geo-thick`（尺寸/粗细＝点径或线宽）。预览界面「BG Pattern 背景纹」下方有「纹理间距 Tile Gap / 纹理粗细 Stroke」两个数字框（对应 style_json 的 `element.bg_gap` / `bg_thick`）。本组变量里**只写兜底值**：`var(--el-geo-gap, <原设计值>)`、`var(--el-geo-thick, <原设计值>)` —— 不填控件时回退模板原值（非破坏性），填了才统一缩放所有接入纹理。starfield / gradient_overlay 构图特殊，暂未接入。

> ⚠️ **契约块是"机械重复"部分**：复制粘贴即可，不要为了"简洁"删掉。缺了它该装饰在画布上不显示（引擎 BASE_CSS 没有主合成）。详见 §8 案例 0 / 6。

### 4.2 伪元素类模板（文本类，按 §2.4 占指定伪元素）
```css
.gallery-card[data-style-element-float="tamagotchi_label"]::before {
  content: "TAMAGOTCHI";
  position: absolute; top: 5px; left: 50%; transform: translateX(-50%);
  font-size: 10px; letter-spacing: 1px; color: var(--card-accent);
  font-family: monospace; pointer-events: none; z-index: 3;
}
```
规则：`position:absolute`（卡片已 `position:relative`）；`z-index:3`；`pointer-events:none`；**不要**在伪元素类写 `background-image`（污染画布）；`content` 用固定字面量（见 §8 案例 4）。

### 4.3 正交类模板（不抢背景/伪元素）
```css
/* stamp_perforation：mask 四边镂空齿孔。⚠️ 每张遮罩必须用 100% 维度瓦片铺满整卡，
   否则只覆盖边缘条 → mask-composite:intersect 把整卡内部判为「未覆盖=透明」→ 卡片整体消失。 */
.gallery-card[data-style-element-edge="stamp_perforation"] {
  --sp-r: 4px; --sp-g: 13px;
  -webkit-mask:
    radial-gradient(circle var(--sp-r) at 50% 0,    #0000 96%, #000) repeat-x 0 0 / var(--sp-g) 100%,
    radial-gradient(circle var(--sp-r) at 50% 100%, #0000 96%, #000) repeat-x 0 0 / var(--sp-g) 100%,
    radial-gradient(circle var(--sp-r) at 0 50%,    #0000 96%, #000) repeat-y 0 0 / 100% var(--sp-g),
    radial-gradient(circle var(--sp-r) at 100% 50%, #0000 96%, #000) repeat-y 0 0 / 100% var(--sp-g);
  -webkit-mask-composite: source-in, source-in, source-in;
          mask:
    radial-gradient(circle var(--sp-r) at 50% 0,    #0000 96%, #000) repeat-x 0 0 / var(--sp-g) 100%,
    radial-gradient(circle var(--sp-r) at 50% 100%, #0000 96%, #000) repeat-x 0 0 / var(--sp-g) 100%,
    radial-gradient(circle var(--sp-r) at 0 50%,    #0000 96%, #000) repeat-y 0 0 / 100% var(--sp-g),
    radial-gradient(circle var(--sp-r) at 100% 50%, #0000 96%, #000) repeat-y 0 0 / 100% var(--sp-g);
          mask-composite: intersect;
}
.gallery-card[data-style-element-edge="notched_corner"] {
  clip-path: polygon(0 0, calc(100% - 14px) 0, 100% 14px, 100% 100%, 0 100%);
}
```

## 5. 位置参数（锚点定位）

同一装饰贴任意角/边，无需另建 DB 条目。`style_json.element` 加位置字段，引擎注入 CSS 变量，一份模板覆盖 8 锚点。

**8 锚点**：四角（top-left / top-right / bottom-left / bottom-right）+ 四边居中（top-center / right-center / bottom-center / left-center）。
**字段**（缺省 `'native'` = 沿用模板原生位置）：`corner_badge_pos` / `floating_deco_pos`（8 锚点）；`edge_deco_pos`（仅四角）。

**引擎行为**：角标/浮动把锚点翻译成 inline CSS 变量挂卡根——`--el-{corner|float}-anchor-pos`、`--el-{subdim}-pos-top/right/bottom/left`、`--el-{subdim}-pos-tf`（居中补偿 transform）；边缘发射 `data-style-element-edge-anchor`；角标发射 `data-style-element-corner-anchor`（8 锚点皆可，`page_fold` 用它切 `--pf-angle`，`corner_ribbon` 用它切朝向）。

**模板消费写法**：
- **背景型**（circle_stamp / dot_status / scatter_dots）：位置变量改 `var()` 兜底——`--el-corner-pos-1: var(--el-corner-anchor-pos, top 6px right 6px);`
- **伪元素型**（corner_ribbon ::after / tamagotchi_label ::before）：`top/right/bottom/left/transform` 全走变量，原生兜底。
  - **朝向规则（corner_ribbon）**：四角必须**镜像**非平移（见 §7）；`transform: var(--el-corner-pos-tf, translate(0,0)) rotate(45deg);`（左上/右下→`-45deg`；四边→`0/90deg`）。
  - ⚠️ `transform` 兜底必须是合法 `translate(0,0)`，**绝不可 `none`**（混入 `none` 整条声明失效）。
- **隔离层型**（floating_circle `.card-deco-layer::before`）：`top/right/bottom/left/transform` 全走 `--el-float-pos-*`，原生兜底卡内右下角。

**偏移量设计期固定**：锚点决定贴哪角，离角多远由各模板 `var()` 兜底值定（移动后统一 12px）。要不同离角距离改自己模板兜底值，无需引擎改动。

**方向性元素**：`art_deco_diamond`（满宽条带，无"角"）不参与切换；`page_fold` 移到对角需翻转渐变角（`--pf-angle`：top-left=135deg / bottom-left=45deg / bottom-right=315deg / 原生右上=225deg），四边居中回落原生。

## 6. 多组件组合的约束与最佳实践（新增章节）

单组件怎么写见 §4。本章讲**多个装饰同时启用**时的交互规则——手册此前对此几乎沉默，是反复踩坑的主因（星空 × 浮动圆即典型案例）。

### 6.1 各子维度的槽位独占范围（白纸黑字）
| 子维度 | 占用资源 | 独占范围 |
|---|---|---|
| `corner_badge` | 14 槽画布 + 伪元素/clip | corner-1,2（背景型）/ `::after`（ribbon）/ `::before`（label）/ clip（`page_fold`、`notched_corner`） |
| `edge_deco` | 14 槽画布 + mask/clip | edge-1..4（bracket/tape）/ mask（stamp_perforation）/ clip（notched_corner） |
| `bg_pattern` | 14 槽画布 | bg-1..4 |
| `floating_deco` | 14 槽画布（scatter_dots）或隔离层（floating_circle） | float-1,2（scatter_dots 走画布）；floating_circle 走 `.card-deco-layer::before`（**不占画布 float 槽**） |
| 文本类（ribbon/label/diamond） | 伪元素 | `.gallery-card::after`(ribbon) / `::before`(label) / `.card-deco-layer::before+::after`(diamond) |

**规则**：同一画布组（corner/edge/bg/float）内，多个装饰**可同时开**（靠 §2.3 的逐字一致契约共存）；文本类与背景类天然正交，永远 ✅；但**同一伪元素槽被两个装饰争用则后者覆盖前者**（见 6.3 仲裁）。

### 6.2 安全组合矩阵
| 组合 | 是否安全 | 说明 |
|---|---|---|
| bg_pattern × corner_badge(背景型) | ✅ | 各占 bg / corner 槽，契约共存 |
| bg_pattern × floating_deco(scatter_dots) | ✅ | 各占 bg / float 槽 |
| bg_pattern × floating_deco(floating_circle) | ✅ | 圆在隔离层，与画布正交，永不争 |
| corner_ribbon × tamagotchi_label | ✅ | 分占 `::after` / `::before` |
| corner_ribbon × art_deco_diamond | ✅ | ribbon=`::after`，diamond=`.card-deco-layer`，解耦 |
| 任意背景 × 任意文本类 | ✅ | 画布 vs 伪元素正交 |
| 两个装饰抢同一伪元素（如 ribbon × 另一也想用 `::after` 的） | ❌ | 后者覆盖前者，需错开或改造 |
| 两个装饰抢同一画布槽且**其中一个偏离契约**（缺主合成/夹裸字） | ❌ | 层叠抹掉另一组图层，见 §8 案例 0 / 6 |

### 6.3 冲突发生时的仲裁策略（引擎实际行为）
1. **画布层（background-*）**：多个背景模板同卡 → 同特异性、**源码顺序后者胜属性**；但因主合成逐字一致，胜出规则引用的仍是全部 14 槽变量，故结果正确（只要都守契约）。一旦有模板违约，违约者或被违约者整组图层异常。
2. **伪元素层**：`.gallery-card::before/::after` 与 `.card-deco-layer::before/::after` 各自独立；**同一伪元素被两条规则命中 → 同特异性后者胜**，表现为一个装饰覆盖另一个（不报错）。因此文本类装饰必须按 §2.4 分配表各占其位，不得越界。
3. **隔离层（floating_circle）**：独占 `.card-deco-layer::before`，因 `floating_deco` 是单选维度（与 diamond 互斥），该伪元素对其永远空闲，**结构上不可能被其它装饰争用**——这是"被连坐元素"应照搬的外科手术式修复范式（见 §8 案例 7）。

### 6.4 单卡装饰总数上限
- 背景类不限量，可全开（受 §2.3 契约保护）。
- 文本类（ribbon/label/diamond）三者互不争用，最多同时 3 个。
- 单卡装饰总数建议 ≤ 5（corner/bg/edge/float + 文本合计）；结构性 header_deco/side_accent/divider 不计入。
- 硬约束仅伪元素 4 槽（卡片根 `::before`/`::after` 各一 + `.card-deco-layer` `::before`/`::after` 各一）。

## 7. 设计经验沉淀（方向性元素「对角镜像」原则）

凡是"贴角/沿边"的**方向性**装饰（`page_fold` / `corner_ribbon` / `notched_corner` / `art_deco_diamond`），移到对角**必须镜像而非平移**：
- ↘↖ 对角（右上/左下）用**正向**；↙↗ 对角（左上/右下）用**反向**（翻角：左上 `135deg`/右下 `315deg`；丝带：左上/右下 `rotate(-45deg)`）。
- 四边居中：丝带长边**平行**于所在边（顶/底边→横 `0deg`、左/右边→竖 `90deg`）。
- 摆放错（平移不镜像）症状：丝带变贯穿卡身对角斜杠；翻角折痕翻到卡外。

## 8. 常见入库反模式（踩过的坑，逐条对照）

### 案例 0 · 画布层叠争用（历史根因，仍是当前唯一系统性风险）
**现象**：多装饰同卡时互相打架——有的装饰消失、有的变成平铺、改位置会带动背景、甚至出现平铺的多个圆。
**错因（根本）**：多个背景模板各自把 14 槽主合成写在 `.gallery-card` 上，二者 `background-image` 同特异性，CSS 层叠只能留"后注入的那条"整体生效。**只要各模板的主合成块逐字一致、且各自只 SET 本组槽位变量，这条"后者胜"其实是安全的**（胜出规则引用的仍是全部 14 槽变量）。真正的破坏来自：① 某模板把别的组的槽位写死 `none`（旧 starfield 故障，见案例 1）；② 某模板**偏离/缺失**主合成块（手改、删"冗余"、或用旧模板）；③ 在 `var()` 外夹裸关键字（见案例 6）。任一违约都会让层叠把别组的图层整组抹掉或平铺——表现与"抢 background-image 独占权"一致。这不是"图层顺序"也不是"亮度"。
**对（当前架构）**：主合成**必须由每个背景类模板各自携带、且逐字一致**（见 §2.3 契约 + §4.1 模板）。缺主合成的模板在画布上不显示；改主合成的模板会连坐别人。**已被连坐的元素**（如历史上 floating_circle 因与 bg 共用画布被覆盖）走"隔离到专属层"的外科手术式修复（见案例 7），而非重排/收归整条画布。
**注意**：2026-07-25 曾出 `element_composite_reorder_20260725.sql`（改图层顺序）与 `element_strip_composite_20260725.sql`（主合成收归引擎 BASE_CSS）——**整轮因实测"验证页几乎不显示"已作废**，引擎已回退 `20260724a`、DB 已回退到 reorder 前。**不要再执行这两份 SQL**（它们与当前架构相反：当前要求模板自带主合成，而 strip 要求模板删主合成）。回退见 `element_revert_reorder_20260725.sql`。

### 案例 1 · 主合成把别的组槽位硬编码 `none`（历史坑，现已结构性消除）
**现象**：旧架构下新写 bg_pattern 后，同卡开 floating_circle / 角标会消失或无法随 `floating_deco_pos` 移动。
**错因**：主合成里 corner/edge/float 槽写成字面 `none` 而非 `var(--el-*, none)`，写死 `none` 那条把同开的浮动/角标整组抹掉。
**对**：主合成现已统一为全 `var()` 引用的逐字契约（见 §4.1）；新模板不再写死 `none`。
**实测样本**：`starfield`(id=48) 旧模板写死 `none` 的故障经 `starfield_fix_20260724.sql` 已修复并落地（DB 现状已是全 `var()` + 自带主合成块）；但"平铺 6 圆"的真正成因见案例 0 + 时间线，并非写死 `none`。

### 案例 2 · 跨组写槽位变量
**现象**：星星被画进浮动层，浮动圆变成平铺星点（"出现 6 个浮动圆"）。
**错因**：bg 装饰写了 `--el-float-*`（本该只写 `--el-bg-*`），污染浮动槽。
**对**：背景类只写自己组的 `--el-<本组>-*`，绝不碰其它组（新铁律第 2 条）。

> **星空 starfield 实况时间线（2026-07-26 校正版）**：
> - **id=48 当前 DB 状态（核实）**：`css_template` 声明 `--el-bg-1..4` 变量 **并携带完整的逐字一致 14 槽主合成块**（`starfield_fix_20260724.sql` 把写死的 `none` 改成全 `var()`，保留主合成）。这是正确的——背景类模板必须有主合成块，否则画布不显示。
> - **"6 个平铺悬浮圆"的真实成因（终版结论）**：历史上 floating_circle 与 bg_pattern **共用 14 槽画布**（floating_circle 当时写 `--el-float-1` 占 float 槽），多装饰同卡时 `background-image` 层叠只留一条胜出 + 旧锚点把圆推到卡外 → 表现为"圆被平铺/消失/无法移动"。根因是**层叠争用 + 共用画布被连坐**，不是亮度、不是写死 none（那是另一个独立故障）。
> - **当前修复（2026-07-25 落地、已取代 reorder/strip 轮）**：**floating_circle(id=34) 脱离画布、隔离到 `.card-deco-layer::before`**（单条 UPDATE `element_floating_circle_deco_layer_20260725.sql`），读引擎发射的 `--el-float-pos-*` 锚点变量，与 bg 画布正交，永不争。此"外科手术式隔离"是"被连坐元素"的标准修复范式（见案例 7）。starfield 维持原画布契约不变。
> - **2026-07-25 的 reorder/strip 轮已整体作废**：回退见 `element_revert_reorder_20260725.sql`；引擎回退 `20260724a`。`element_composite_reorder_20260725.sql` / `element_strip_composite_20260725.sql` / `element_robust_test.html` 均已移至 `_deprecated/`，**不要再执行/参考**。
> - **案例 2 仍是有效警告**：agent 草稿把星点写进 `--el-float-*` 会污染浮动槽，但那是未入库草稿，非当时成因。
> - **实证**：用 `capsule-preview.html` / `gallery.html` 勾选 starfield + floating_circle + 任意组合，验证圆可随 `floating_deco_pos` 移动、不消失、不平铺（注：`element_compat_test.html` 已不在仓库、`element_robust_test.html` 属作废架构，均不作为验证依据）。

### 案例 3 · 选择器漏前导点
**现象**：装饰完全不显示、不报错，极难排查。
**错因**：`css_template` 写成 `gallery-card[...]`（漏 `.`），浏览器当成标签名，永远命中不了 class。
**对**：选择器必须 `.gallery-card[...]`。

### 案例 4 · 伪元素 `content` 用两参 `attr()`
**现象**：伪元素不生成。
**错因**：`content: attr(name, fallback)` 在 `content` 上不被浏览器支持（且引擎未发射对应属性）。
**对**：`content` 用固定字面量（`"NEW"` / `"\25C6..."`）。

### 案例 5 · 探出卡外被 `overflow:hidden` 裁掉
**现象**：旋转 45° 贴角的丝带被切掉一块。
**错因**：卡片根 `overflow:hidden`，装饰锚定 `right:0` 配 `translate` 外推。
**对**：丝带锚定卡内右上角（`top/right` 取正值），勿外推。

### 案例 6 · SQL 模板里 `var()` 之外夹裸 CSS 关键字（隐蔽，致命）
**现象**：某装饰的圆形被平铺满整张卡（如 floating_circle 隔离前的 140px 圆出现 6 个），但 DevTools 里 `background-repeat` 看起来"差不多对"。
**错因**：在 `background-repeat`（或 `image`/`size`/`position`）的某个 `var()` 之后，不小心多拼了一个**裸关键字**，例如：
```css
background-repeat: var(--el-bg-rep-1, no-repeat) repeat , var(--el-bg-rep-2, no-repeat), ...;
                                                  ^^^^^ 裸 repeat（非法）
```
浏览器把 `no-repeat repeat` 解析为**非法值**，整条 `background-repeat` 声明失效 → 回退到默认 `repeat` → 所有图层（含 float 槽的 140px 圆）被平铺。DevTools 常把"已解析成功的 `var(--el-bg-rep-1, no-repeat)` 部分"折叠显示，裸关键字不易肉眼发现。
**对（写 SQL 的铁律）**：
1. **主合成块里除 `var(...)`、`var()` 内的兜底字面量（`none`/`auto`/`no-repeat`）、逗号、空格外，不得出现任何其它裸 CSS 关键字。** 兜底字面量只允许出现在 `var()` 的第二个参数里（如 `var(--el-x, none)`），不得独立裸奔。
2. 用脚本拼接 `css_template` 字符串时格外小心：每槽严格 `var(--el-xxx, <兜底>)` 一项，项间仅逗号分隔，末尾无多余关键字。
3. **建议加校验**：入库前用正则/小脚本扫一遍主合成四个属性，检测 `var()` 之外是否有 `repeat|no-repeat|auto|none` 等裸关键字裸奔（这些只能出现在 `var(..., <x>)` 内）。肉眼不可靠。
4. 最小模板见 §4.1——契约块直接复制粘贴，不要手敲。

### 案例 7 · 被连坐元素 → 隔离到专属层（外科手术式修复范式）
**现象**：某装饰本身稳，但因与别的装饰共用 14 槽画布，组合时总被覆盖/平铺/冻结（历史上 floating_circle 即如此）。
**错因**：多个装饰挤在同一块 `background-image` 画布上，层叠争用不可避免会"连坐"个别元素。
**对（范式）**：对"被连坐"的元素，不要重排/收归整条画布（reorder→strip→BASE_CSS 三轮大重构已证伪，见案例 0 注意项），而是**把它搬到一个独占的渲染层**：
- `floating_circle`(id=34)：因 `floating_deco` 是单选维度（与 `art_deco_diamond` 互斥），`.card-deco-layer::before` 对其永远空闲 → 把圆画在 `.card-deco-layer::before` 上，读引擎已发射的 `--el-float-pos-*` 锚点变量，**完全脱离 14 槽画布**。单条 UPDATE（`element_floating_circle_deco_layer_20260725.sql`）、零引擎改动、可回退。
- 此范式可作为其它"被连坐"背景类元素的通用解法：找一张永远空闲的层（伪元素/隔离层），把该元素移过去。
**实测**：starfield + floating_circle 同开 → 单个干净可移动圆，零冲突。

## 10. 入库 SQL 模板

### 10.1 维度组件入库（通用）
```sql
-- <dim> 取 layout/typo/border/deco/effect/element；<sub_dim> 取对应子维度
insert into style_<dim>_options (sub_dim, value, label, description, css_template, sort_order, is_enabled)
values ('<sub_dim>', '<value>', '<中文标签>', '<效果描述>', '<完整CSS>',
  (select coalesce(max(sort_order),0)+1 from style_<dim>_options where sub_dim='<sub_dim>'), true);
```

### 10.2 改现有组件 CSS（幂等 fix）
```sql
update style_element_options set css_template = '<完整CSS>' where id = <id>;  -- id 见 §9
```

### 10.3 配色入库（harmony_palette 需给种子色）
```sql
insert into style_palette_options (value, label, sub_dim, bg, text_color, accent, muted, extra_colors, description, sort_order)
values ('analogous_teal_violet','青紫邻近','harmony_palette',
  '#0D9488','#A78BFA','#0D9488','#A78BFA',
  '{"accent_2":"#C084FC","bg_secondary":"#134E4A"}', '青色到紫色邻近过渡',
  (select coalesce(max(sort_order),0)+1 from style_palette_options where sub_dim='harmony_palette'));
```

### 10.4 容器组入库（给 key 字段）
```sql
insert into style_container_group_options
  (group_code, group_name, category, description, layout_ref, repeat_mode,
   field_slot_map, slot_deco_map, layout_slot_map, extra_css, sort_order, is_enabled)
values ('cg_my_layout','我的布局','creative','说明',
  '2col_equal','once',
  '{"highlights":"slot_a","avatar":"slot_b"}'::jsonb,
  '{"slot_a":"deco:bubble_style.wechat_left"}'::jsonb,
  '{"slot_a":1,"slot_b":2}'::jsonb,
  '.container-group.cg_my_layout{...}',
  (select coalesce(max(sort_order),0)+1 from style_container_group_options), true);
```

> **SQL 入库前自检（呼应 §8 案例 6）**：背景类 `css_template` 写完后，跑一遍校验——确认主合成四属性中除 `var(...)`、逗号、空格、`var()` 内兜底字面量外**无裸关键字**；确认选择器带前导 `.`；确认无跨组写槽、无硬编码 hex。建议把这段校验固化成小脚本随 SQL 一起交付。

## 11. 验证流程（入库前必做）

1. 用 `capsule-preview.html`（实时预览）或 `gallery.html`（瀑布流）加载目标卡片，核对三种效果：① 独立显示 ② 四者叠加（corner+bg+edge+float 同开）③ 文本类与背景类共存。
2. 重点盯：新 bg_pattern 同开 `floating_circle` 时，浮动圆**必须仍能随 `floating_deco_pos` 移动、不消失、不平铺**（案例 0/2/6/7 的复发点）；并核对主合成块逐字一致、无裸关键字（案例 6）。
3. 确认无 `!important`、无硬编码 hex、无漏前导点、无跨组写槽。
4. 产出 SQL 交用户执行；用户执行后硬刷新预览页（Ctrl+Shift+R）确认线上生效。
> 注：`element_compat_test.html` 已不在仓库、`element_robust_test.html` 属作废架构（在 `_deprecated/`），均不作为当前验证依据；以 `capsule-preview.html` / `gallery.html` 为准。

## 12. 请求礼仪

- `value` 用 **snake_case**，标签中文，描述一句话说清效果。
- 一条请求集中说清：用在哪个维度/子维度、解决什么主题、CSS 片段是什么。
- 不要一次塞几十条；theme 驱动、少而精。
- 用户执行后组件即生效，你后续设计就能直接引用。
